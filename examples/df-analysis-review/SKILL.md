# 外部分析与评审

这是供现有 Agent 使用的状态机模块。读取状态说明，使用你已有的能力完成任务，并根据实际证据维护正确的状态跳转。

## 先读取定义

- [状态机总文档](references/state-machine.md)：完整 Mermaid 状态图，以及各状态、跳转条件、质量和节点策略。
- [结构化定义](references/state-machine.json)：核对状态 ID、层级和迁移引用。
- [标签描述](references/state-machine.xml)：同一份定义的结构化文本。
- [状态记录模板](assets/state-record.template.json)：当前任务使用的记录格式。

## 每次调用

- 先读取 [实例与实时展示](references/execution.md)，用 `scripts/run.mjs start --workspace <当前任务工作区绝对路径>` 创建本次实例。开启展示时会自动打开实时窗口；使用助手上报实际事件与提交迁移，避免界面与状态记录脱节。
- 新任务始终 start；仅在用户明确继续某个未完成任务时 resume 并指定原实例目录。完成后自动归档，不能再次使用旧实例继续新任务。不要把任务状态写进 Skill 安装目录。
- 使用返回的 handoff 查看当前状态目标、进入条件、质量、工具和策略。用宿主已有工具自主完成工作，再按 decisionFormat 提交本次证据与条件结论。只记录检查结论、证据引用与简要依据。
- 不能确认条件时保持状态，按策略核实或等待。多个条件冲突或未定义路径时指出缺口，不把未知条件当作通过。
- 外部工具受理不等于完成。保留原任务标识，先查询原任务，不因超时重复提交。无法自动唤醒时记录待办，之后显式 resume。
- 子状态机通过 __enter__ 进入、__return__ 返回父层，再判断父层出路；顶层结束状态经 __finish__ 确认后归档。以助手返回的候选路径为准。定义固定在实例目录中，不静默替换进行中版本。

## 条件判断与循环

判断与循环节点支持多条入路和出路。每次从任一入路到达后，结合到达路径与当前上下文，按节点的分支选择策略检查各条出路；只有条件、必要质量项与目标进入条件均成立时才沿对应路径迁移。没有匹配或条件不确定时保留当前状态；多项同时满足时遵循显式的选择策略，策略未说明则核实或澄清。

循环节点通过 loopRole=continue 的路径进入本轮工作，完成后沿定义中的返回路径回到循环节点，重新检查本轮条件；通过 loopRole=exit 的路径退出。记录实际经过的迁移与每轮结果，不把上轮的通过结论直接用于本轮。

## 能力边界

Skill 提供说明与状态记录约定，不创建工具连接、不授予权限，也不提供后台调度。缺少工具或材料时说明缺口。遵循宿主与用户的现有指令。
