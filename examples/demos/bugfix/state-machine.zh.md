# 修复 Bug 并验证

- 状态机：`demo-bugfix`
- 定义版本：`1.0.0`
- 入口：复现问题（`reproduce`）

## 用途

> 修复购物车合计忽略数量的问题，交付最小改动和回归报告，并保留修复前后的真实测试结果。

## 状态机总览

以下为完整状态机定义。连线标注迁移 ID、跳转条件及必要质量项；返工、异常和循环均保留。子状态机内部结束后返回父层级。

```mermaid
stateDiagram-v2
    direction TB
    state "交付修复（结束状态）" as s_done
    state "最小修复（工作状态）" as s_fix
    state "逐项回归（列表）" as s_regression
    state "复现问题（工作状态）" as s_reproduce
    state "检查测试结果（条件判断）" as s_verify
    [*] --> s_reproduce
    s_fix --> s_verify : patch-ready · 最小修复已准备好，可以测试。；必要质量：focused-diff
    s_regression --> s_done : regressions-passed · 所有回归用例通过，修复报告已完成。
    s_reproduce --> s_fix : reproduced · 问题已稳定复现。；必要质量：reproduced
    s_verify --> s_fix : test-failed · 【返工 / 异常】原始测试仍失败。
    s_verify --> s_regression : test-passed · 原始测试通过。；必要质量：test-passed
    s_done --> [*]
```


## 推进方式

使用自己的 Agent 读取本定义、检查实际证据并维护状态。无需调用 DecoupleFlow 或其他决策服务。

## 使用约定

由宿主 Agent 使用本状态机。节点内如何完成工作由 Agent 自主决定；条件满足后，依据已定义的迁移更新当前状态。

业务材料和工具由宿主管理。未知条件不等于满足条件；工具请求受理不等于任务完成。仅对迁移显式引用的质量项进行该次跳转的必要检查，其余质量项用于改进结果。

子状态机有独立入口；进入子状态机后从内部入口开始，内部结束状态表示返回父状态机，再检查该子状态机节点的出边。记录完整状态路径，避免混淆不同层级。

|---|---|---|---|

## 跳转一览

| 跳转 ID | 从 | 到 | 条件 | 路径类型 | 必要质量项 |
|---|---|---|---|---|---|
| `patch-ready` | 最小修复 | 检查测试结果 | 最小修复已准备好，可以测试。 | 正常 | `focused-diff` |

| `test-failed` | 检查测试结果 | 最小修复 | 原始测试仍失败。 | 返工 / 异常 | — |
| `test-passed` | 检查测试结果 | 逐项回归 | 原始测试通过。 | 正常 | `test-passed` |
