# 带来源的选型简报

- 状态机：`demo-research`
- 定义版本：`1.0.0`
- 入口：明确选型标准（`scope`）

## 用途

> 为需要离线使用、Markdown 导出的个人用户，对比三个虚构笔记工具。每条结论指向给定来源，未提供的信息保留为未知。

## 状态机总览

以下为完整状态机定义。连线标注迁移 ID、跳转条件及必要质量项；返工、异常和循环均保留。子状态机内部结束后返回父层级。

```mermaid
stateDiagram-v2
    direction TB
    state "交付选型简报（结束状态）" as s_done
    state "编写对比简报（工作状态）" as s_draft
    state "核查每条结论（条件判断）" as s_review
    state "明确选型标准（工作状态）" as s_scope
    state "逐份核查资料（列表）" as s_sources
    [*] --> s_scope
    s_review --> s_done : approved · 简报有据可查，并回应选型问题。；必要质量：traceable、unknowns-marked、answers-brief
    s_draft --> s_review : draft-ready · 已有可核查的对比稿。
    s_review --> s_draft : needs-revision · 【返工 / 异常】结论缺乏支持、缺少引用，或把未知写成了事实。
    s_scope --> s_sources : scoped · 问题与标准已明确。；必要质量：criteria-clear
    s_sources --> s_draft : sources-read · 三份资料均已核查，摘录已保存。
    s_done --> [*]
```


## 推进方式

使用自己的 Agent 读取本定义、检查实际证据并维护状态。无需调用 DecoupleFlow 或其他决策服务。

## 使用约定

由宿主 Agent 使用本状态机。节点内如何完成工作由 Agent 自主决定；条件满足后，依据已定义的迁移更新当前状态。

业务材料和工具由宿主管理。未知条件不等于满足条件；工具请求受理不等于任务完成。仅对迁移显式引用的质量项进行该次跳转的必要检查，其余质量项用于改进结果。

子状态机有独立入口；进入子状态机后从内部入口开始，内部结束状态表示返回父状态机，再检查该子状态机节点的出边。记录完整状态路径，避免混淆不同层级。
