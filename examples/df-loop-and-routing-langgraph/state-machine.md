# 循环与条件分支

- 状态机：`loop-and-routing`
- 定义版本：`1.0.0`
- 入口：准备待办项（`prepare`）

## 用途

> 逐项处理任务，每轮按质量与资料条件选择路径，直到全部完成或用户停止。

## 状态机总览

以下为完整状态机定义。连线标注迁移 ID、跳转条件及必要质量项；返工、异常和循环均保留。子状态机内部结束后返回父层级。

```mermaid
stateDiagram-v2
    direction TB
    state "补充资料（等待状态）" as s_clarify
    state "全部交付（结束状态）" as s_done
    state "准备待办项（工作状态）" as s_prepare
    state "检查是否继续（循环）" as s_repeat
    state "判断当前结果（条件判断）" as s_review
    state "修订当前项（工作状态）" as s_revise
    state "停止处理（结束状态）" as s_stopped
    state "处理当前项（工作状态）" as s_work
    [*] --> s_prepare
    s_review --> s_revise : changes · 【返工 / 异常】资料完整，但质量尚未通过
    s_repeat --> s_work : continue · 【继续循环】仍有待办项，且用户未要求停止
    s_repeat --> s_done : finish · 【退出循环】全部项目已通过质量检查
    s_review --> s_clarify : missing · 缺少必要资料
    s_review --> s_repeat : passed · 资料完整且质量通过，本项已标记完成；必要质量：item-approved
    s_work --> s_review : processed · 当前项已有可检查的结果
    s_revise --> s_review : revised · 本轮修订已完成
    s_prepare --> s_repeat : start · 待办项目和要求已明确
    s_repeat --> s_stopped : stop · 【退出循环】用户明确要求停止
    s_clarify --> s_review : supplemented · 缺少的资料已补齐
    s_done --> [*]
    s_stopped --> [*]
```


## 推进方式

使用自己的 Agent 读取本定义、检查实际证据并维护状态。无需调用 DecoupleFlow 或其他决策服务。

## 使用约定

由宿主 Agent 使用本状态机。节点内如何完成工作由 Agent 自主决定；条件满足后，依据已定义的迁移更新当前状态。

业务材料和工具由宿主管理。未知条件不等于满足条件；工具请求受理不等于任务完成。仅对迁移显式引用的质量项进行该次跳转的必要检查，其余质量项用于改进结果。

子状态机有独立入口；进入子状态机后从内部入口开始，内部结束状态表示返回父状态机，再检查该子状态机节点的出边。记录完整状态路径，避免混淆不同层级。

## 检查是否继续 · repeat

类型：循环

### 状态说明

> 每轮检查剩余事项与停止要求，决定继续处理或退出。

### 进入条件

_未填写_

### 质量条件

未单独定义。

### 进入路径

任一入路满足条件后可以到达此节点；每次到达后重新判断出路。

- 来自 **判断当前结果**，迁移 `passed`：资料完整且质量通过，本项已标记完成

- 来自 **准备待办项**，迁移 `start`：待办项目和要求已明确

### 分支选择策略

> 用户明确要求停止时优先进入停止路径；否则，全部完成时交付，仍有待办时继续。证据不足时保留当前状态并核实。

### 循环规则

进入循环节点时检查继续与退出条件。继续条件成立后进入对应目标，完成本轮后沿已定义的返回路径回到此节点；每轮重新检查条件与质量项。退出条件明确满足后，沿对应退出路径进入下一状态。循环次数、实际工作与等待由宿主 Agent 管理。
